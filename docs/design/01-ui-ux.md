# UI / UX 설계

시각 목업은 디자인 캔버스에 있다 (화면 5종 + 사용자 흐름).
이 문서는 그 목업이 담고 있는 결정을 글로 남긴 것이다.

## 화면 구성

한 화면이다. 화면 전환도, 로그인도, 저장도 없다.

```
┌────────────────────────────────────────────────────┐
│ location maker            [CSV 내려받기] [링크 복사] │
├──────────────┬─────────────────────────────────────┤
│ 주소 입력      │                                     │
│ ┌──────────┐ │                                     │
│ │ 한 줄에   │ │              지 도                   │
│ │ 주소 하나 │ │         (번호 붙은 마커)             │
│ └──────────┘ │                                     │
│ [지도에 표시] │                                     │
│ ──────────── │                                     │
│ 찾음 10 실패 2│                                     │
│ ① 테헤란로152 │                                     │
│ ② 을지로 65  │                                     │
│ ⚠ 양화로 45  │                                     │
│   [고쳐서다시]│                                     │
│ ④ 판교역로235 │                                     │
└──────────────┴─────────────────────────────────────┘
```

**실패한 줄도 번호를 쓴다** — ⚠ 자리는 ③ 이고, 다음 줄이 ④ 다. 번호는 "찾은 것 중 몇
번째" 가 아니라 **입력 줄 번호**이기 때문이다. 건너뛰면 사용자가 목록의 세 번째 줄과
지도의 ④ 를 짝지을 수 없게 된다.

좌측 패널 400px 고정, 우측 지도가 나머지를 채운다. 모바일(~400px)에서는 지도가 위,
결과 목록이 아래 바텀 시트로 쌓인다.

## 화면 상태 5종

| 상태 | 좌측 패널 | 지도 |
| --- | --- | --- |
| 첫 진입 | 빈 입력창 + 사용법 3줄 + `예시 넣어보기` | 흐린 지도 + "아직 표시할 주소가 없습니다" |
| 조회 중 | 진행률 `7 / 12` + 항목별 상태 + `중단` | 찾은 것부터 하나씩 마커가 찍힘 |
| 결과 | 요약 칩(찾음/실패) + 마커 목록 | 전체가 들어오도록 범위 자동 조정 |
| 일부 실패 | 실패 항목이 원래 자리에 남고 `고쳐서 다시` / `건너뛰기` | 성공한 것만 마커 |
| 키 없음 | 입력은 정상 동작 | 지도 자리에 설정 안내 문구 |

## 핵심 사용자 흐름

1. **붙여넣기** — 엑셀에서 복사한 주소 열을 그대로 넣는다. 줄 하나가 주소 하나.
2. **정리** — 빈 줄과 중복을 걸러 내고, 몇 건을 조회할지 먼저 보여 준다.
3. **좌표 찾기** — 동시 3건씩 조회. 결과가 나오는 대로 마커를 하나씩 찍는다.
4. **한눈에 보기** — 찍힌 마커 전체가 들어오도록 지도 범위를 자동으로 맞춘다.
5. **가져가기** — 주소 목록이 담긴 링크를 복사하거나, 좌표까지 붙은 CSV 를 내려받는다.

실패 경로는 2번으로 돌아간다. `고쳐서 다시`는 원문을 입력창에 되돌려 놓고 재조회하며,
`건너뛰기`는 실패로 확정한다.

## 이 흐름이 지키는 것

- **화면 전환이 없다.** 처음부터 끝까지 한 화면.
- **로그인도 저장도 없다.** 상태는 주소창에만 담긴다.
- **입력 목록과 마커 목록의 순서가 끝까지 같다.**

## 못 찾은 주소가 이 앱의 진짜 화면이다

주소 스무 개를 넣으면 한두 개는 반드시 실패한다. 오타, 옛 지번, 신축 건물 때문이다.
실패를 조용히 버리면 사용자는 마커 개수가 왜 다른지 모른 채 잘못된 지도를 믿게 된다.

그래서 **실패는 성공과 같은 목록에, 원래 입력한 문장 그대로, 원래 순서 자리에 남는다.**
이것이 화면 설계에서 가장 중요한 결정이다.

## 목업에 대한 단서

- 정적 목업이다. 동작하는 프로토타입이 아니다.
- 지도 영역은 실제 지도 SDK 가 들어갈 자리를 그린 것이고, 마커 위치는 예시다.
- 모바일 목업에 가짜 상태바나 가상 키보드는 그리지 않았다. 실제 기기에서 OS 가 그 위에
  렌더링한다.
