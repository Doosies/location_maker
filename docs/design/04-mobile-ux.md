# 모바일 최적화와 UI/UX 개선 설계

이 문서는 2026-09-16 에 실제 화면을 360px·390px·1280px 에서 찍어 본 뒤,
무엇이 왜 문제이고 어떻게 고치는지를 남긴 것이다. [01-ui-ux.md](./01-ui-ux.md) 가
정한 것(한 화면, 실패 줄 보존, 번호 불변식)은 그대로 두고 **배치와 시각 언어만** 다시 짠다.

## 1. 지금 무엇이 잘못됐나

주소 여섯 줄(실패 한 줄 포함)을 넣고 찍은 화면 기준이다.

## 2. 무엇을 바꾸는가 — 한 문장

**지도를 문서의 한 블록에서 화면의 바닥으로 옮기고, 입력과 목록을 그 위에 얹는다.**

모바일에서는 지도가 화면 전체를 채우고 그 위에 바텀 시트가 뜬다. 데스크톱에서는
지도가 오른쪽을 꽉 채우고 왼쪽 패널만 안에서 스크롤된다. 양쪽 다 **지도가 절대
시야에서 사라지지 않는다.**

## 3. 앱 셸

문서 흐름(`max-width` + 세로 스크롤)을 버리고 **높이가 고정된 셸**로 간다.

```
html, body, #root { height: 100% }
.app { display: grid; height: 100%; overflow: hidden }
```

`100vh` 가 아니라 `100%` + `100dvh` 를 쓴다. 모바일 브라우저의 주소창이 접히고 펴질 때
`100vh` 는 따라오지 않아 지도 아래가 잘리거나 빈 띠가 생긴다.

페이지 전체 스크롤이 사라지므로, 스크롤은 **시트 안쪽에서만** 일어난다.

## 4. 모바일 (< 52rem)

```
┌─────────────────────────┐
│ ▤ location maker    ⋯   │ ← 앱바 (safe-area-top 만큼 내려옴)
│                         │
│                         │
│         지  도           │ ← 화면 전체. 마커가 여기 찍힌다
│       ① ② ④ ⑤ ⑥        │
│                         │
│                         │
├─────────────────────────┤
│         ────            │ ← 손잡이 (누르면 다음 단계)
│  찾음 5   실패 1         │
│ ─────────────────────── │
│ ① 서울 강남구 테헤란로… │ ← 시트 안에서만 스크롤
│ ② 서울 중구 을지로 65   │
└─────────────────────────┘
```

### 4.1 바텀 시트 3단

| 단계 | 높이 | 보이는 것 | 언제 |
| --- | --- | --- | --- |
| `peek` | `10rem` | 손잡이 + 요약 한 줄 + 목록 한 자락 + 바닥 띠 | 지도를 크게 보고 싶을 때 |
| `half` | `48dvh` | 위 + 목록 두세 줄 | **조회를 시작하면 여기로 내려온다** |
| `full` | `calc(100% - 3.25rem - var(--safe-top))` | 입력창까지 전부 | **첫 진입 기본값**, 주소를 고칠 때 |

`peek` 이 손잡이만 남기지 않는 이유는, 시트 안에 든 것이 상자 밖으로 흘러넘치면
**보이지 않는데 Tab 으로는 닿는 버튼**이 생기기 때문이다. 손잡이(44) + 머리 한 줄(30) +
목록 한 자락(14) + 바닥 띠(65) 가 다 들어가는 높이를 `peek` 으로 잡는다. 남는 한 자락은
아래에 더 있다는 표시이기도 하다. `full` 이 `safe-top` 까지 빼는 것은
앱바가 그만큼 내려오기 때문이다 — 빼지 않으면 노치 기기에서 시트가 앱바를 덮는다.

- 단계 전환은 **손잡이 탭**(`<button aria-expanded>`)과 **드래그** 둘 다 된다.
  탭을 먼저 만든다 — 제스처는 기기·브라우저마다 어긋나지만 탭은 어디서나 같고,
  테스트로 고정할 수 있다. 드래그는 Pointer Events 로 얹되, 실패해도 탭이 남는다.
- 상태가 바뀌면 자동으로 단계가 옮겨 간다: 조회를 시작하면 `half`(마커가 찍히는 것을
  봐야 한다), 실패가 있으면 그대로 `half`(고칠 줄이 보여야 한다).
- `prefers-reduced-motion` 이면 전환 애니메이션을 끈다.

### 4.2 시트 안에 들어가는 것

순서는 `입력 → 안내 → 목록` 그대로다. **아무것도 DOM 에서 빼지 않는다.**

요약은 시트 머리(`.sheet__head`)에 한 줄로 둔다 — `6곳 중 5곳 확인 · 1곳 실패`. 목록이
가진 요약 칩(`찾음 5` / `실패 1`)과 **다른 문장**이어야 한다. 같은 글이 화면에 둘이면
그 글로 화면을 찾는 저니 테스트가 어느 쪽을 가리키는지 알 수 없다. 좁은 화면에서는 칩을,
넓은 화면에서는 머리 한 줄을 각각 숨기되 DOM 에는 둘 다 남는다.

진행 표시는 시트가 아니라 **지도 위**에 띄운다. 시트를 내려도 몇 건째인지와 `중단` 이
남아야 하기 때문이다. 넓은 화면에서는 왼쪽 칸의 제 행에 놓는다 — 자리를 주지 않으면
그리드가 암시적 행을 만들어 지도 컨테이너 높이를 조회 중에 줄였다 늘린다. Kakao 는
스타일에 의한 컨테이너 크기 변경을 스스로 relayout 하지 않으므로 타일 없는 띠가 남는다.

입력창의 `rows` 는 8 → 4 로 줄인다. 모바일 가상 키보드가 올라오면 화면의 절반이
사라지는데, 8줄짜리 입력창은 그 남은 절반을 혼자 다 쓴다. 넓은 화면도 같은 4줄이다 —
폭에 따라 줄 수가 달라질 이유가 없고, 넘치는 줄은 스크롤되며 손잡이로 늘릴 수 있다.

### 4.3 액션 이동

`CSV 내려받기`·`링크 복사`를 헤더에서 **시트 바닥의 고정 바**로 내린다. 둘 다 결과가
나온 뒤에 쓰는 버튼이고, 엄지가 닿는 곳은 화면 아래다. 앱바에는 제목만 남는다.

## 5. 데스크톱 (≥ 52rem)

같은 DOM, 미디어 쿼리만 다르다.

```
┌──────────────────────────────────────────────┐
│ location maker                                │
├───────────────┬──────────────────────────────┤
│ 주소 입력      │                              │
│ [        ]    │                              │
│ [지도에 표시]  │           지  도              │  ← 뷰포트를 꽉 채움
│ 찾음 5 실패 1  │                              │
│ ① …          │                              │  ← 왼쪽 패널만 안에서 스크롤
│ ② …          │                              │
│ [CSV] [링크]  │                              │
└───────────────┴──────────────────────────────┘
```

- `.app` 은 `grid-template-columns: 26rem minmax(0, 1fr)`, 행은 `auto auto minmax(0, 1fr)`
  (앱바 · 진행 띠 · 시트), 높이 `100%`. 지도는 세 행을 다 쓴다.
- 시트는 `transform` 을 버리고 그냥 왼쪽 칸이 된다 (`--sheet-height` 를 쓰지 않는다).
- 지도는 `height: 100%`.

DOM 이 두 레이아웃에서 같으므로 단위 테스트(jsdom, CSS 없음)와 E2E(1280px)가
지금 보는 것을 그대로 본다.

## 6. 시각 언어

지도 앱이다. 바탕은 지도 타일에 얹혀도 읽히는 밝은 중성색이고, 강조는 마커 색 하나다.

### 6.1 색 토큰

| 토큰 | 라이트 | 다크 | 쓰임 |
| --- | --- | --- | --- |
| `--bg` | `#eef1f6` | `#0d1117` | 앱 바닥 (지도 로딩 전) |
| `--surface` | `#ffffff` | `#161b22` | 시트·카드 |
| `--surface-2` | `#f5f7fa` | `#1c232c` | 항목 바탕 |
| `--ink` | `#111826` | `#e7edf5` | 본문 |
| `--ink-muted` | `#5b6675` | `#94a3b5` | 보조 설명 |
| `--line` | `#dce3ec` | `#2b3441` | 테두리 |
| `--accent` | `#1f4fd8` | `#5b8cff` | 마커·주요 버튼 |
| `--accent-ink` | `#ffffff` | `#0d1117` | 강조 위 글자 |
| `--ok` | `#0f7b52` | `#3ecf8e` | 찾음 |
| `--warn` | `#b4520f` | `#f0a35e` | 건너뜀 |
| `--danger` | `#b3261e` | `#ff8a80` | 못 찾음·오류 |

중성색은 순수 회색이 아니라 강조색 쪽으로 살짝 파랗게 기울였다. 지도 타일 옆에
놓였을 때 카드가 따로 노는 것처럼 보이지 않게 하려는 것이다.

**모든 색은 `:root` 에 한 번 선언하고, `@media (prefers-color-scheme: dark)` 에서
값만 바꾼다.** 컴포넌트는 토큰만 쓴다 — 지금처럼 `#1f2937` 을 규칙 안에 박으면
한쪽 테마에서 반드시 안 보인다.

### 6.2 상태를 색만으로 말하지 않는다

| 상태 | 뱃지 | 테두리 | 글 |
| --- | --- | --- | --- |
| 찾음 | 번호 (파랑 채움) | 기본 | 도로명 주소 |
| 못 찾음 / 오류 | `!` (빨강 채움) | 왼쪽 3px 빨강 띠 | 실패 사유 |
| 건너뜀 | 번호 (흐림) | 기본, 항목 흐림 | `건너뜀` |
| 대기 / 조회 중 | 번호 (외곽선) | 기본 | `조회 중` |

색각 이상과 흑백 출력을 위해 **모양(뱃지 글자)과 글**이 색과 같은 말을 한다.
지금은 `⚠` 를 쓰는데, 이모지는 기기마다 다르게 그려지고 크기도 제각각이라
글자 `!` 로 바꾼다.

### 6.3 터치 크기

- 모든 버튼 `min-height: 2.75rem` (44px) — 이미 지켜지고 있다.
- 목록 항목 제목 버튼을 **항목 전체**로 넓힌다. 카드 어디를 눌러도 그 마커로 간다.
- 지도 마커를 `1.75rem` → `2rem`(32px) 로 키우고 `clickable` 로 만들어, 누르면
  그 목록 항목이 시트에서 보이도록 스크롤한다. 목록 → 지도만 되던 길이 양방향이 된다.

### 6.4 그 밖

- `env(safe-area-inset-*)` 를 앱바 위쪽과 시트 바닥 액션 바에 넣는다.
- 앱 셸과 시트는 `overflow: hidden` 이 아니라 **`overflow: clip`** 이다. `hidden` 은 잘라
  내면서 스크롤 컨테이너가 되므로, 흘러넘친 자식에 포커스가 가면 브라우저가 그 상자를
  스크롤하고 스크롤바가 없어 사용자가 되돌릴 수 없다.
- 지도 범위는 `setBounds` 의 여백 인자로 **덮인 만큼 안쪽에** 맞춘다. 덮개는
  `[data-map-overlay]` 사각형과 지도 사각형이 겹치는지를 재서 정하므로, 넓은 화면에서는
  저절로 0 이 된다.
- 지도 위에 얹히는 것(앱바·시트)은 `backdrop-filter: blur` 와 반투명 바탕.
- 포커스 링은 `outline: 2px solid var(--accent)` + `offset: 2px` 로 통일.

## 8. 하지 않는 것

- 지도 API 교체, 백엔드 추가, 상태 저장 — 범위 밖이다.
- CSS 프레임워크 도입. 스타일시트가 400줄 남짓이라 토큰만으로 충분하고,
  번들에 100KB 를 더할 이유가 없다.
- 다크 모드 수동 토글. OS 설정을 따른다 — 이 앱에는 설정 화면이 없다.
