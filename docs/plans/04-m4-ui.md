### 계획에서 달라진 것

**`건너뛰기` 를 위해 `EntryStatus` 에 `skipped` 를 더했다.** 설계는 건너뛰기를
"실패로 확정한다" 고만 적어 두었는데, 기존 상태로는 확정한 줄과 아직 손대지 않은 실패
줄을 구분할 수 없었다. 구분이 없으면 건너뛴 줄에도 계속 `고쳐서 다시` 를 권하게 된다.
요약 칩에서는 `notFound` · `failed` 와 같은 "실패" 로 센다.

**`고쳐서 다시` 는 입력창을 덮어쓰지 않는다.** 그 줄이 이미 입력창에 있으면 그대로 두고,
없으면 끝에 붙인 뒤 포커스를 옮긴다. 통째로 바꾸면 나머지 줄이 사라진다.

**진행 표시에 `LM-PROGRESS`, 조립에 `LM-APP` PREFIX 를 새로 뒀다.** 원래 산출물 목록에는
테스트 파일이 셋이었는데, 중단 동작과 전체 연결은 컴포넌트 단위 테스트로는 잡히지 않는다.

## 작업

### 1. 스토어 — `src/state/store.ts`

`prefix: LM-STORE`. `useSyncExternalStore` 기반. 상태 라이브러리는 쓰지 않는다.

| 케이스 | 기대 |
| --- | --- |
| `setEntries(list)` | 배열이 통째로 교체된다 |
| `updateEntry(id, patch)` | **그 항목만** 바뀐다. 길이와 순서는 그대로 |
| 조회 중 여러 번 update | 순서가 절대 흐트러지지 않는다 |
| `reset()` | 빈 상태로 돌아간다 |

**불변식:** 배열 순서 = 입력 줄 순서 = 마커 번호. 이 테스트를 명시적으로 하나 둔다.

### 2. 입력 — `src/ui/AddressInput.tsx`

`prefix: LM-INPUT`.

- 여러 줄 textarea. placeholder 에 예시 3줄
- 줄 수를 실시간으로 보여 준다
- 비어 있으면 `지도에 표시` 버튼이 비활성
- `예시 넣어보기` 버튼 — 첫 진입에서 바로 굴려 볼 수 있게
- `비우기` 버튼

### 3. 결과 목록 — `src/ui/ResultList.tsx`, `ResultItem.tsx`

`prefix: LM-LIST`.

- 상태별 렌더 — `pending` / `loading` / `found` / `notFound` / `failed`
- `found` — 번호 배지, 라벨, 지역·건물명
- `notFound` / `failed` — 경고색, 실패 이유 한 줄, `고쳐서 다시` / `건너뛰기`
- 요약 칩 — `찾음 n` / `실패 n`
- 긴 주소가 잘리지 않고 줄바꿈된다

### 4. 진행 표시

- 진행률 `7 / 12` 와 막대
- `중단` 버튼이 `AbortController` 를 부른다
- 긴 작업 전에 무엇이 도는지 보인다 (사용자가 멈춘 줄 알면 안 된다)

### 5. 조립 — `src/App.tsx`

- 파싱 → 큐 → 스토어를 잇는다
- 어댑터는 **주입**한다. M4 에서는 가짜 어댑터를 꽂는다
- 지도 자리에는 M1 에서 만든 안내 문구가 그대로 남아 있다

### 6. 접근성과 반응형

- 모바일 터치 대상 44px 이상
- textarea 에 라벨
- 포커스 링이 보인다
- 400px 폭에서 한 줄로 쌓인다
