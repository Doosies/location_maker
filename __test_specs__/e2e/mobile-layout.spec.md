# 좁은 화면 저니

이 앱이 하는 일은 주소를 지도에 찍는 것이다. 그 지도가 스크롤해야 나오면 앱이 켜지긴
해도 제 일을 못 한다. 이전 레이아웃이 정확히 그랬다 — 390px 에서 지도 상단이 스크롤
1,400px 아래였고, **단위 테스트도 1280px 저니도 그것을 못 잡았다.** 폭을 실제로 좁혀
보는 테스트가 하나 있어야 한다.

뷰포트는 390 × 844 다 (`playwright.config.ts` 의 `mobile` 프로젝트).

### UC-LME-MOBILE-001 390px 에서 지도가 스크롤 없이 첫 화면에 보인다

- **Given** 앱을 390px 폭으로 열고
- **When** 아무것도 하지 않으면
- **Then** 지도가 뷰포트 안에 있고, 문서가 뷰포트보다 높지도 넓지도 않다

가로 스크롤은 좁은 화면에서 가장 흔한 고장이라 같이 본다.

### UC-LME-MOBILE-002 조회하면 시트가 내려가고 마커가 보인다

- **Given** 주소 세 줄을 넣고
- **When** `지도에 표시` 를 누르면
- **Then** 시트가 `half` 로 내려가고 마커가 뷰포트 안에 보인다

마커가 하나씩 찍히는 것을 봐야 하는데 시트가 화면을 다 덮고 있으면 못 본다.

### UC-LME-MOBILE-003 손잡이를 누르면 시트가 접혔다 펴진다

- **Given** 시트가 `full` 에 있고
- **When** 손잡이를 눌러 `peek` 으로 보내면
- **Then** `data-snap` 이 바뀌고 **시트의 실제 높이도 줄어든다**

높이까지 보는 이유는, `data-snap` 만 바뀌고 CSS 가 따라오지 않으면 화면에서는 아무 일도
일어나지 않기 때문이다. 단위 테스트는 그 차이를 볼 수 없다.

### UC-LME-MOBILE-004 마커를 누르면 그 줄이 목록에서 보인다

- **Given** 마커가 세 개 찍혀 있고
- **When** 3번 마커를 누르면
- **Then** 세 번째 줄이 시트 안에서 보이는 자리로 온다

목록 → 지도는 처음부터 있었지만 그 반대가 없었다.
