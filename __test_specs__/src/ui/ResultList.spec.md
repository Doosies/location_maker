# 결과 목록

주소 스무 개를 넣으면 한두 개는 반드시 실패한다. 오타, 옛 지번, 신축 건물 때문이다.
실패를 조용히 버리면 사용자는 마커 개수가 왜 다른지 모른 채 잘못된 지도를 믿게 된다.

**그래서 실패는 성공과 같은 목록에, 원래 입력한 문장 그대로, 원래 순서 자리에 남는다.**
화면 설계에서 가장 중요한 결정이고, 이 문서의 대부분은 그것을 지키는 이야기다.

### UC-LM-LIST-001 비어 있으면 안내 문구를 띄운다

- **Given** 항목이 하나도 없고
- **When** 목록을 렌더하면
- **Then** 무엇을 하면 되는지 한 줄이 보인다

### UC-LM-LIST-002 실패 항목이 원래 자리에 원문 그대로 남는다

- **Given** 찾음·못 찾음·찾음 순서의 항목 셋이 있고
- **When** 목록을 렌더하면
- **Then** 항목이 셋이고 가운데 항목에 원문이 그대로 있다

### UC-LM-LIST-003 요약 칩이 찾음과 실패를 센다

- **Given** 찾음 둘·실패 하나가 있고
- **When** 목록을 렌더하면
- **Then** `찾음 2` 와 `실패 1` 이 보인다

### UC-LM-LIST-004 찾은 항목에는 목록 자리와 같은 번호가 붙는다

- **Given** 항목 셋이 있고
- **When** 목록을 렌더하면
- **Then** 첫째에 1, 셋째에 3 이 붙는다

이 번호가 곧 지도의 마커 번호다.

### UC-LM-LIST-005 실패 항목에만 고쳐서 다시·건너뛰기가 붙는다

- **Given** 실패 항목이 하나 있고
- **When** 두 버튼을 누르면
- **Then** 버튼은 하나씩만 있고, 각 콜백이 그 항목으로 불린다

### UC-LM-LIST-006 건너뛴 항목은 자리에 남되 더 권하지 않는다

- **Given** `skipped` 항목이 하나 있고
- **When** 목록을 렌더하면
- **Then** 원문과 `건너뜀` 은 보이고 `고쳐서 다시` 는 없다

사용자가 이미 결정한 줄이다. 자리와 원문은 남기되 다시 권하지 않는다.

### UC-LM-LIST-007 장소명으로 찾은 항목은 그렇다고 표시한다

- **Given** `matchedBy: 'keyword'` 인 항목이 있고
- **When** 목록을 렌더하면
- **Then** `장소명으로 찾음` 이 보인다

지번으로 찾은 것과 상호로 찾은 것은 정확도가 다르다. 사용자가 구분할 수 있어야 한다.

### UC-LM-LIST-008 조회 중 항목은 조회 중으로 보인다

- **Given** `loading` 항목이 있고
- **When** 목록을 렌더하면
- **Then** `조회 중` 이 보인다

### UC-LM-LIST-009 찾은 항목을 고르면 그 항목으로 알린다

- **Given** 찾은 항목이 있고
- **When** 그 원문을 누르면
- **Then** `onSelect` 가 그 항목으로 불린다

지도를 그 마커로 옮기는 유일한 통로다.

### UC-LM-LIST-010 좌표가 없는 항목은 고를 수 없다

- **Given** 실패한 항목이 있고
- **When** 목록을 렌더하면
- **Then** 그 원문은 버튼이 아니다

마커가 없는 줄에 눌리는 버튼을 두면 아무 일도 일어나지 않는 것이 고장으로 보인다.
