# 바텀 시트

좁은 화면에서 지도는 화면 그 자체이고, 입력과 목록은 그 위에 얹히는 시트다. 시트는
`peek`(요약만) · `half`(기본) · `full`(입력창까지) 세 자리를 오간다.

**탭이 먼저다.** 드래그는 기기와 브라우저마다 어긋나지만 손잡이를 누르는 것은 어디서나
같고 테스트로 고정할 수 있다. 그래서 손잡이는 진짜 `button` 이고, 포인터 드래그는 그
위에 얹는다 — 드래그가 안 먹는 환경에서도 탭이 남는다.

### UC-LM-SHEET-001 손잡이를 누를 때마다 자리가 돈다

- **Given** 시트가 `peek` 에 있고
- **When** 손잡이를 세 번 누르면
- **Then** `half` → `full` → 다시 `peek` 로 돌아온다

돌아올 길이 있어야 막다른 골목이 없다.

### UC-LM-SHEET-002 손잡이가 접힘 여부를 aria-expanded 로 알린다

- **Given** 시트가 `peek` 에 있고
- **When** 손잡이의 `aria-expanded` 를 보면
- **Then** `false` 이고, 한 번 누르면 `true` 가 된다

손잡이는 그림이 아니라 버튼이다. 눈으로 보는 것과 같은 말을 스크린 리더에도 해야 한다.

### UC-LM-SHEET-003 어느 자리에서도 머리·내용·바닥이 DOM 에 남는다

- **Given** 시트가 `peek` 에 있고
- **When** 머리·내용·바닥을 찾으면
- **Then** 셋 다 있다

자리는 CSS 높이일 뿐이다. 내용을 지우면 좁은 화면에서만 사라지는 요소가 생기고, 그러면
넓은 화면에서 도는 테스트가 좁은 화면의 고장을 못 잡는다.

### UC-LM-SHEET-004 끌어서 옮기면 놓은 높이에 가장 가까운 자리에 선다

- **Given** 시트가 `peek` 에 있고 화면 높이가 800px 이고
- **When** 손잡이를 400px 위로 끌었다 놓으면
- **Then** 높이 480px 에 가장 가까운 `half` 로 자리를 옮긴다

손가락을 놓은 자리와 시트가 서는 자리가 크게 다르면 시트가 제멋대로 움직이는 것처럼 보인다.
