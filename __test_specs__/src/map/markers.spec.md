# 마커

지도에 무엇을 찍을지 정하는 순수 계산이다. SDK 를 모른다.

**번호는 목록 자리 번호다.** "찾은 것 중 몇 번째" 가 아니다. 실패한 줄이 번호를
건너뛰면 사용자가 목록의 세 번째 줄과 지도의 마커를 짝지을 수 없게 된다.

### UC-LM-MARKER-001 찾은 항목만 마커가 된다

- **Given** `found` · `notFound` · `loading` 이 하나씩 있고
- **When** 마커를 계산하면
- **Then** `found` 하나만 나온다

### UC-LM-MARKER-002 번호는 목록 자리 번호다

- **Given** 첫째가 `found`, 둘째가 `failed`, 셋째가 `found` 이고
- **When** 마커를 계산하면
- **Then** 번호가 1 과 **3** 이다

### UC-LM-MARKER-003 인포윈도우에 원문과 좌표가 들어간다

- **Given** 도로명이 원문과 다른 항목이 있고
- **When** 마커를 계산하면
- **Then** 원문 · 도로명 · 좌표 세 줄이 순서대로 담긴다

좌표를 보여 주는 이유는 사용자가 결과를 의심할 때 확인할 단서가 그것뿐이어서다.

### UC-LM-MARKER-004 도로명이 원문과 같으면 두 번 쓰지 않는다

- **Given** 도로명이 원문과 같은 항목이 있고
- **When** 마커를 계산하면
- **Then** 줄이 둘이다

### UC-LM-MARKER-005 바뀐 것만 골라낸다

- **Given** 이미 마커 둘이 있고, 새 목록에 하나는 그대로·하나는 빠지고·하나가 늘었으며
- **When** 차이를 내면
- **Then** 늘어난 하나만 `added`, 빠진 하나만 `removed`, `moved` 는 비어 있다

매번 전부 지우고 다시 그리면 조회가 도는 동안 마커가 계속 깜빡인다. 열 줄이면 열 번이다.

### UC-LM-MARKER-006 번호만 바뀌어도 갱신 대상이다

- **Given** 좌표는 같고 번호만 2 에서 1 로 바뀌었고
- **When** 차이를 내면
- **Then** `moved` 에 들어간다

좌표만 보면 번호가 틀어진 채로 남는다.
