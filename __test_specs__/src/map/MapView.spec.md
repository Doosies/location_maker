# 지도 화면

SDK 를 주입받아 지도를 만들고 마커를 맞춘다. 테스트는 **무엇을 시켰는지만 기록하는
가짜 SDK** 로 돈다 — 실제 지도를 그리지 않고 네트워크도 키도 쓰지 않는다.

### UC-LM-MAP-001 찾은 항목마다 마커를 올린다

- **Given** `found` 하나와 `notFound` 하나가 있고
- **When** 지도를 렌더하면
- **Then** 오버레이가 하나 만들어져 지도에 붙는다

### UC-LM-MAP-002 마커에 목록 자리 번호가 찍힌다

- **Given** 첫째가 실패하고 둘째가 `found` 이며
- **When** 지도를 렌더하면
- **Then** 그 마커의 내용이 **2** 다

실패한 줄이 1번을 차지한다. 이것이 목록과 지도를 눈으로 짝지을 유일한 단서다.

### UC-LM-MAP-003 마커가 하나면 범위 대신 중심과 고정 레벨을 쓴다

- **Given** `found` 가 하나 있고
- **When** 지도를 렌더하면
- **Then** 그 좌표로 중심이 옮겨지고 레벨이 고정값이다

### UC-LM-MAP-004 마커가 여럿이면 전부 담는 범위를 만든다

- **Given** 서울과 부산에 하나씩 있고
- **When** 지도를 렌더하면
- **Then** 남서 · 북동 두 점이 bounds 에 들어간다

### UC-LM-MAP-005 항목이 늘어도 기존 마커를 다시 만들지 않는다

- **Given** 마커 하나가 이미 올라가 있고
- **When** 항목이 하나 늘어 다시 렌더되면
- **Then** 오버레이는 둘만 만들어진다 (기존 것을 다시 만들지 않는다)

조회는 한 건씩 끝난다. 매번 다시 그리면 열 줄짜리 입력에서 마커가 열 번 깜빡인다.

### UC-LM-MAP-009 마커가 그대로면 범위를 다시 맞추지 않는다

- **Given** 마커 둘이 이미 올라가 있고
- **When** 마커가 늘지 않는 갱신(실패 줄 추가)이 오면
- **Then** 범위를 다시 만들지 않는다

조회 중에는 상태만 바뀌는 렌더가 계속 온다. 그때마다 범위를 맞추면 사용자가 끌어 놓은
지도가 마커와 무관한 갱신에 원위치된다.

### UC-LM-MAP-006 고른 항목의 마커로 지도를 옮긴다

- **Given** 마커가 둘 있고
- **When** 둘째를 고르면
- **Then** 그 좌표로 `panTo` 한다

### UC-LM-MAP-007 언마운트하면 마커를 걷어 낸다

- **Given** 마커가 올라가 있고
- **When** 지도를 언마운트하면
- **Then** 오버레이가 모두 지도에서 내려간다

남겨 두면 다음 지도에 유령 마커가 뜬다.

### UC-LM-MAP-008 키가 없으면 지도 대신 안내를 띄운다

- **Given** 키가 빈 문자열이고
- **When** 지도를 렌더하면
- **Then** 넣어야 할 변수 이름이 담긴 안내가 보인다

흰 화면이 되면 설정이 빠진 것과 코드가 깨진 것을 구분할 수 없다.

### UC-LM-MAP-010 마커를 누르면 그 줄로 되돌아온다

- **Given** 마커가 하나 찍혀 있고
- **When** 그 마커를 누르면
- **Then** 그 줄의 id 로 `onMarkerSelect` 가 불린다

목록 → 지도는 처음부터 있었지만 그 반대가 없었다. 마커가 스무 개 찍힌 화면에서
"저 점이 어느 주소였지" 를 물을 방법이 없었다는 뜻이다.

`CustomOverlay` 의 `content` 로 **요소를 넘기고 그 요소에 리스너를 건다.** HTML 문자열을
주면 오버레이가 만든 DOM 에 닿을 길이 없어, 클릭이 지도 컨테이너까지 버블되기를
기대하는 수밖에 없다 — `clickable` 오버레이의 이벤트를 SDK 가 어떻게 다루는지에 앱이
매달리게 되고, 그 답은 실기기에서만 알 수 있다. 요소를 들고 있으면 그 질문이 사라진다.

### UC-LM-MAP-011 고른 항목의 마커에만 테가 둘린다

- **Given** 마커가 둘 있고
- **When** 둘째를 고르면
- **Then** 둘째 마커에만 `marker--focused` 가 붙는다

어느 점을 고른 것인지 지도에서도 보여야 한다. 목록만 바뀌면 지도는 남의 일이 된다.

### UC-LM-MAP-012 범위를 맞출 때 지도를 덮은 만큼 안쪽으로 맞춘다

- **Given** 마커가 둘 있고
- **When** 범위를 맞추면
- **Then** `setBounds` 에 네 방향 여백 인자를 함께 준다

좁은 화면에서 지도는 화면 전체이고 앱바와 시트가 그 위에 얹힌다. 여백 없이 맞추면
마커 절반이 시트 뒤에 숨는다 — "마커가 찍히는 것을 보면서" 가 이 화면의 요점인데
정작 절반을 못 보게 된다.

덮개는 이름이 아니라 **겹치는지 재서** 정한다 (`[data-map-overlay]` 의 사각형과 지도
컨테이너의 사각형). 넓은 화면에서는 같은 요소들이 지도와 가로로 겹치지 않아 저절로
0 이 되므로, 폭을 묻는 분기가 필요 없다. jsdom 은 배치를 하지 않아 덮개가 늘 0 이라,
이 테스트가 고정하는 것은 **여백 인자를 준다는 사실**이다.
