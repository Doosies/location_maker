# 링크에 담는 주소 목록

저장소도 로그인도 없는 앱이라 **링크가 곧 저장**이다. 그래서 이 파일이 지켜야 할 것은
둘이다 — 넣은 순서 그대로 돌아오는 것, 그리고 어떤 입력에도 던지지 않는 것.

**좌표는 담지 않는다.** 링크를 연 쪽이 다시 조회하면 되고, 좌표까지 담으면 링크가 길어진다.
해시(`#`)를 쓰는 이유는 GitHub Pages 가 경로 라우팅에 404 를 내기 때문이다.

인코딩은 **base64url** 이다. 퍼센트 인코딩은 한글 한 글자를 9자로 만들어, 실제 주소 20줄이
2887자가 된다. base64url 은 같은 줄이 1330자다.

### UC-LM-URL-001 넣은 순서 그대로 돌아온다

- **Given** 주소 셋이 있고
- **When** 인코딩한 뒤 디코딩하면
- **Then** 같은 순서의 같은 배열이다

목록 순서 = 입력 줄 순서 = 마커 번호. 링크를 지나도 같아야 한다.

### UC-LM-URL-002 한글이 깨지지 않는다

- **Given** 한글 주소가 있고
- **When** 왕복시키면
- **Then** 원문 그대로다

### UC-LM-URL-003 빈 목록이면 해시를 붙이지 않는다

- **Given** 빈 목록(또는 공백뿐인 줄)이고
- **When** 인코딩하면
- **Then** 해시가 빈 문자열이다

아무것도 넣지 않은 상태에서 링크를 복사해도 주소창이 지저분해지지 않는다.

### UC-LM-URL-004 망가진 해시에도 던지지 않는다

- **Given** base64 가 아닌 값 · base64 지만 UTF-8 이 아닌 값 · 다른 키 · 빈 해시가 있고
- **When** 디코딩하면
- **Then** 예외 없이 빈 목록이다

링크는 손으로 잘리고 붙는 물건이다. 던지면 앱이 흰 화면이 되는데, 그건 사용자가 고칠 수
없는 고장이다.

### UC-LM-URL-005 너무 길면 자르지 않고 거절한다

- **Given** 주소가 아주 많고
- **When** 인코딩하면
- **Then** `ok: false`, `reason: 'too-long'` 과 상한을 돌려준다

몰래 자르면 주소 몇 개가 사라진 링크가 열린다. 열리기는 하므로 사용자가 알아채기 어렵다.

### UC-LM-URL-006 앞뒤 공백과 빈 줄은 담지 않는다

- **Given** 공백이 붙은 줄과 빈 줄이 섞여 있고
- **When** 왕복시키면
- **Then** 다듬어진 줄만 남는다

### UC-LM-URL-007 실제 형태의 주소 스무 줄이 링크 하나에 들어간다

- **Given** 시·도와 건물명이 붙은 주소 20줄이 있고
- **When** 인코딩하면
- **Then** 상한 안에 들어가고 그대로 복원된다

퍼센트 인코딩은 한글 한 글자를 9자로 만들어 이 20줄이 2887자였다. base64url 로는 1330자다.
흔한 사용(스무 줄 안팎)이 막히면 링크 기능 자체가 쓸모없어진다.
