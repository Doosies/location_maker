# 지오코딩 큐

주소 스무 개를 한꺼번에 던지면 남의 서비스에 실례고, 하나씩 보내면 사용자가 기다린다.
그래서 동시 세 건으로 흘려보내고, 한 건이 끝날 때마다 바로 화면에 올린다.

큐는 `GeocodePort` 만 받는 순수 함수다. `window` 도 `kakao` 도 모른다. 덕분에 가짜
어댑터만으로 아래 케이스가 전부 검증된다.

쿼터 초과는 다른 실패와 다르게 다룬다. 한 건이 쿼터로 막혔다면 나머지도 막힐 것이고,
계속 던지면 남은 한도까지 태운다. 그래서 그 자리에서 전체를 멈춘다.

### UC-LM-QUEUE-001 동시 실행이 정해진 수를 넘지 않는다

- **Given** 항목 10개와 동시 실행 3 이 주어지고
- **When** 큐를 돌리면
- **Then** 어느 순간에도 진행 중인 조회가 3을 넘지 않는다

### UC-LM-QUEUE-002 한 건이 끝날 때마다 즉시 알린다

- **Given** 항목 여럿이 있고
- **When** 그중 하나의 조회가 끝나면
- **Then** 전체가 끝나기 전에 그 항목의 `onResult` 가 불린다

### UC-LM-QUEUE-003 찾은 항목은 found 가 된다

- **Given** 어댑터가 좌표를 돌려주고
- **When** 큐를 돌리면
- **Then** 그 항목이 `found` 가 되고 `place` 가 채워지며 `raw` 는 그대로다

### UC-LM-QUEUE-004 결과가 없으면 notFound 가 된다

- **Given** 어댑터가 `zero_result` 를 돌려주고
- **When** 큐를 돌리면
- **Then** 그 항목이 `notFound` 가 되고 `failure` 가 담긴다

### UC-LM-QUEUE-005 한 건이 실패해도 나머지는 계속 돈다

- **Given** 가운데 항목 하나가 네트워크 오류로 실패하고
- **When** 큐를 돌리면
- **Then** 그 항목은 `failed` 가 되고 나머지 항목은 모두 조회된다

### UC-LM-QUEUE-006 쿼터 초과는 전체를 멈춘다

- **Given** 세 번째 조회가 `quota` 로 실패하고
- **When** 큐를 돌리면
- **Then** 새 조회를 시작하지 않고, 손대지 않은 항목은 `pending` 으로 남는다

### UC-LM-QUEUE-007 중단 신호를 받으면 새로 시작하지 않는다

- **Given** 큐가 도는 중에 `signal.abort()` 가 호출되고
- **When** 진행 중이던 조회가 끝나면
- **Then** 남은 항목은 `pending` 으로 남고 조회 횟수가 더 늘지 않는다

### UC-LM-QUEUE-008 같은 주소는 한 번만 조회한다

- **Given** `normalized` 가 같은 항목이 셋 있고
- **When** 큐를 돌리면
- **Then** 어댑터는 한 번만 불리고 세 항목 모두 같은 결과를 받는다

### UC-LM-QUEUE-009 빈 배열은 아무것도 하지 않는다

- **Given** 항목이 없고
- **When** 큐를 돌리면
- **Then** 어댑터가 불리지 않고 즉시 끝난다
